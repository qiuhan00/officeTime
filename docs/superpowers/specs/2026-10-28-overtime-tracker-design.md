# 加班记录应用 设计文档

日期：2026-10-28
状态：待确认

## 1. 意图

给一个人用的上下班打卡与加班统计工具。使用者在华为 Mate 80 上通过主屏图标打开网页使用，数据存放在自己的阿里云轻量服务器上。

要解决的问题：月底想知道这个发薪周期加了多少班，不想再翻聊天记录或靠记忆估算。打卡要尽可能少操作；漏打了要能事后补，补完不影响统计。

## 2. 目标

- 一键记录上班 / 下班，时间以服务器为准
- 主界面顶部显示**本周期**累计加班时长（精确到分钟，显示为“X小时Y分”）
- 日历按自然月展示，每天显示当天加班时长
- 漏打卡可点日历任意一天补录或修改，也可把某天标记为休息日、或删除该天记录
- 设置中可改：周期起始日、加班起算时间、工作日
- **自动识别中国法定节假日和调休日**（默认开启）：法定节假日整天算加班，调休上班日按工作日规则算
- 节假日数据自动更新：服务器定期从公共 CDN 拉取，也可在设置页手动更新
- 数据保存在服务器端数据库，换设备不丢
- 公网可访问，因此必须登录（单用户密码）

## 3. 非目标

- 导出（用户明确不需要）
- 多用户、权限、审批
- 原生鸿蒙 app、桌面卡片、离线缓存
- 运行时逐日调用第三方接口判断节假日（只在后台整体拉取数据，判断全在本地）
- 定位、防代打卡、设备绑定
- 复杂报表、图表、趋势分析

## 4. 反目标

- 打卡流程超过两次点击
- 需要理解“周期”“口径”等概念才能看懂顶部数字
- 任何情况下出现负数或跨周期重复计算

## 5. 界面与交互

整体为手机竖屏单页应用，中文字体，浅色主题。

### 5.1 主界面（布局 A）

自上而下：

1. **统计卡**：小字标注周期范围（如“10月26日–11月25日”），大字显示加班合计（如“32小时35分”）。右侧显示今日已产生的加班（如“今日 +1:30”）。
2. **打卡按钮**：并排两个按钮“上班 09:02”/“下班”。已打过的按钮显示时间并变为浅色；当前可执行的按钮为实心主色。两个都完成后按钮区显示“今日完成”。未打卡时“上班”可点，“下班”置灰。
3. **日历**：自然月网格，周一为第一列。每格显示日号，有加班的显示时长小字（如“1:30”）。加班日浅色底，今天描边。**不属于顶部统计卡所示周期的日期变灰**。左右箭头切换月份。
4. 点击任意日期 → 弹出当天记录面板（详见 5.2）。

顶部统计的周期规则：首次打开或切回当前月时，显示**包含今天的周期**；切到其他月份时，显示**包含该月 1 号的周期**。统计卡始终标注当前所示周期范围，日历上不属于该周期的日期变灰。

### 5.2 当天记录面板（补录用）

从底部弹出，覆盖在当前页上：

- 标题：日期与星期；副标题：当天类型（“工作日 · 19:00 后算加班”/“休息日 · 全天算加班”）
- “上班”行：显示时间或“未打卡”，右侧“修改/补录”
- “下班”行：同上
- “设为休息日/设为工作日”切换
- 按钮：关闭、保存
- 保存时允许只填上班或只填下班（表示“忘了打下班”，该天暂不计入合计；日历上显示小圆点表示记录不完整）
- 若该天被设为休息日/工作日，额外显示“恢复默认”，点击后回到按工作日设置推断
- 底部文字按钮：删除这一天（二次确认）
- 补录时用系统时间选择器，只允许选今天及以前的日期；时间精确到分钟；今天的时间不能晚于当前服务器时间

保存后立即刷新统计与日历，不需要刷新页面。

### 5.3 设置页

- 周期起始日：下拉或数字输入，1–28（默认 26）。说明文案：“每月 26 日到次月 25 日算一个周期”
- 加班起算时间：时间选择（默认 19:00）
- 工作日：周一到周日的多选（默认周一至周五）
- 自动识别节假日：开关，默认开启；下方显示“数据覆盖 2004–2026 · 最后更新 2026-10-28”，旁边“立即更新”按钮，更新中显示进度，失败时提示“更新失败，继续使用现有数据”
- 修改密码
- 退出登录

设置改动立即对统计生效（含历史日期），不做版本快照。

## 6. 业务规则

### 6.1 时间

- 所有打卡以**服务器时间**为准，时区固定 Asia/Shanghai
- 存储日期 `YYYY-MM-DD` 与时间 `HH:mm`（中国无夏令时，存本地墙钟时间即可）
- 显示精确到分钟，不做取整

### 6.2 一天一条记录

每个日期最多一条记录，含：日期、上班时间、下班时间（可空）、是否休息日覆盖（可空）。
上班或下班缺任意一边时，该天不计入加班合计，日历不显示时长，只显示不完整标记。

### 6.3 加班计算

设 `in` 为上班时间，`out` 为下班时间：

- **工作日**：`max(0, out − max(in, 加班起算时间))`。例：09:00–20:23 → 1小时23分；20:00–22:00 → 2小时；09:00–18:30 → 0。
- **休息日**：`out − in`，全天都算。
- 判断某天是工作日还是休息日，优先级从高到低：
  1. 该天的“休息日覆盖”（手动设置）
  2. 自动识别开启、且该日期在节假日数据中：法定节假日为休息日，调休上班日为工作日
  3. “工作日”设置（默认周一至周五）
  4. 兜底：周一至周五为工作日，周六周日为休息日
- 自动识别关闭、或日期不在已下载数据的覆盖范围内时，跳过第 2 条，直接按设置/兜底判断，不报错
- 当天记录面板的副标题显示节假日名称（如“国庆节”），没有名称时显示“工作日/休息日”

### 6.4 跨零点

- 下班打卡若发生在 00:00–06:00 之间，且前一天存在“只有上班没有下班”的记录，则这次下班记到前一天，并保留次日日期时间。
- 手动补录时，若下班时间早于上班时间，视为次日下班，按跨零点处理。
- 跨零点的下班时间参与计算时按“次日”理解，因此时长正确。

### 6.5 打卡状态

- 当天已有上班且无下班 → 只能点“下班”
- 当天已有上班和下班 → 两个按钮都不可点（改时间走补录）
- 当天无记录 → 只能点“上班”
- 上班打卡不受加班起算时间影响
- 前一天仍有未闭合记录、且现在不在 00:00–06:00 时：不阻止今天上班；前一天保持未完成，日历上用标记提示，可点开补录
- **00:00–06:00 的延迟下班**：仅当昨天（紧邻的前一天）存在未闭合记录时，打卡区额外显示“昨天 下班”主按钮，点击记到昨天；同时保留“今天 上班”。更早的缺口通过补录处理。06:00 之后不再提供这个入口

### 6.6 补录校验

- 只能改今天及以前；今天的时间不得晚于当前服务器时间
- 允许只填一边（未完成状态），也可以清除已填的时间
- 补录导致跨零点时（下班早于上班，或下班时间落在 00:00–06:00），下班归属次日；若次日已存在记录，拒绝保存并提示先处理次日记录，不静默覆盖
- 上班时间等于下班时间时，时长记为 0，允许保存
- 服务端在保存前统一校验，前端只做同样的提示，不依赖前端保证正确性

## 7. 技术方案

### 7.1 架构

- 单进程 Web 应用：Node.js（LTS）+ Express，托管静态前端与 JSON API
- 数据库：SQLite（better-sqlite3），文件位于数据卷
- 节假日数据：数据源为 `https://cdn.jsdelivr.net/npm/chinese-days/dist/chinese-days.json`（日期 → 名称映射，含 holidays / workdays / inLieuDays）。镜像内置一份快照作为初始数据，运行时以数据库中的副本为准
- 更新策略：启动时若库中无数据则导入内置快照并尝试拉取；运行中每 7 天后台拉取一次，成功则校验后入库，失败保留旧数据；设置页可手动触发
- 校验：JSON 结构、日期格式、条目数上限（< 1 MB）、覆盖年份合理，任一失败则丢弃本次数据
- 网络：服务器需能访问 `cdn.jsdelivr.net`；不可达时只用现有数据，功能不受影响。内置快照文件入库即用，首次启动无网也能正常判断
- 前端：原生 HTML/CSS/JS，无构建步骤，一个 `index.html` + `app.js` + `styles.css`
- 部署形态：Docker 镜像 + docker-compose（含数据卷）。部署到服务器的方式与访问地址（公网 IP、无域名 HTTPS）在开发测试完成后再定

### 7.2 数据模型

```
settings (单行)
  period_start_day  INTEGER 1..28  默认 26
  overtime_start    TEXT 'HH:mm'   默认 '19:00'
  workdays          TEXT '1,2,3,4,5'  -- 1=周一
  password_hash     TEXT
  updated_at        TEXT

days
  date        TEXT PRIMARY KEY  -- YYYY-MM-DD
  in_at       TEXT NULL         -- HH:mm
  out_at      TEXT NULL         -- HH:mm（跨零点时为次日时间）
  out_next_day INTEGER 0/1      -- out 是否属于次日
  is_rest     INTEGER NULL      -- NULL=按设置推断；1=休息日；0=工作日
  updated_at  TEXT

sessions
  token       TEXT PRIMARY KEY
  created_at  TEXT
  expires_at  TEXT

holiday_data (单行)
  id           INTEGER PRIMARY KEY CHECK (id = 1)
  json         TEXT     -- chinese-days.json 原文
  coverage_min TEXT     -- 数据中最早日期 YYYY-MM-DD
  coverage_max TEXT     -- 数据中最晚日期
  fetched_at   TEXT     -- 最近一次成功拉取/导入时间
```

### 7.3 API

除登录外全部需要会话；未登录返回 401，前端跳登录页。

- `POST /api/login` `{password}` → 设置 HttpOnly Cookie
- `POST /api/logout`
- `POST /api/password` `{oldPassword, newPassword}`
- `GET /api/bootstrap?month=YYYY-MM` → 设置、该月天数与记录、顶部周期范围与合计、今日状态
- `PUT /api/settings` → 覆盖设置，返回新设置及受影响周期合计
- `POST /api/holidays/refresh` → 立即拉取节假日数据，返回覆盖范围与更新时间（失败返回错误与旧数据信息）
- `POST /api/punch` `{type: "in"|"out"}` → 按服务器时间写入，返回最新当日记录
- `PUT /api/days/:date` `{inAt, outAt, isRest}` → 补录/修改（date 只能是今天及以前；`isRest` 传 `null` 表示恢复默认；字段传 `null` 表示清除）

校验规则见 6.6，统一在服务端执行。
- `DELETE /api/days/:date`

计算逻辑（加班、周期、跨零点）集中在服务端一个纯函数模块，前端只做展示。

### 7.4 认证与安全

- 单用户密码，scrypt 哈希存库；首次启动若库中无密码，用环境变量 `INITIAL_PASSWORD` 初始化
- 会话 token 随机 32 字节，存库，有效期 30 天，HttpOnly + SameSite=Lax Cookie
- 登录失败按 IP + 全局计数做简单限流（如 5 次/分钟）
- 所有 SQL 走参数化；输出做 HTML 转义

### 7.5 测试

- 纯函数单测：加班计算（含边界 19:00 整、休息日、跨零点、缺下班）、周期区间计算（含跨年、2 月、起始日 1 和 28）、日期类型判定（法定节假日、调休上班日、普通周末、数据未覆盖的年份回退、手动覆盖优先、自动识别关闭时回退）
- 节假日数据：解析与校验（正常数据、缺字段、超大文件、非法日期）；拉取失败时保留旧数据；手动刷新覆盖旧数据；重启后从库中恢复
- API 集成测试：node:test + 临时 SQLite，覆盖登录、打卡状态流转、补录、删除、设置变更后的重算
- 前端：开发完成后用 Playwright 走一遍主流程（打卡、补录、切月、改设置）

## 9. 本次讨论中由我代定的（供核对）

1. 顶部统计与日历的对应关系：默认“包含今天的周期”；切到其他月份改为“包含该月 1 号的周期”，日历上不属于该周期的日子变灰
2. 一天只允许一条上下班记录
3. 未来日期不可补录；今天不能填晚于当前时间的记录
4. 删除是物理删除，有二次确认
5. 设置修改立即重算历史，不做版本快照
6. 服务器时区固定 Asia/Shanghai，不跟随用户设备
7. 登录为单密码，无用户名
8. 技术栈：Node.js + Express + SQLite，Docker 交付
9. 允许“只有上班”或“只有下班”的不完整记录，不完整的天不计加班，日历上用小圆点提示
10. 允许在 00:00–06:00 给前一天补“下班”（界面上明确标注“昨天”）
11. 补录导致跨零点且次日已有记录时，拒绝保存而不是覆盖
12. 休息日/工作日覆盖可恢复为“按设置”
13. 自动识别节假日默认开启，数据从 jsDelivr 拉取并存入数据库，镜像内置快照作为初值，不逐日调用接口
14. 优先级：手动覆盖 > 自动节假日/调休 > 工作日设置 > 周一到周五兜底
15. 数据未覆盖的年份自动回退到“按设置判断”，不报错，设置页显示数据覆盖范围与最后更新时间
16. 每 7 天自动拉取一次；拉取/校验失败保留旧数据，不影响已记录的历史计算结果

## 10. 验收标准

- 手机上打开即登录页；登录后看到顶部本周期的加班合计与当月日历
- 点“上班”后按钮状态正确切换，服务器时间被记录
- 跨零点下班正确归到前一天，时长正确
- 点日历任一天可补上/修改时间，保存后合计与格子立即更新
- 把某天设为休息日后，该天按“下班 − 上班”重算
- 把周期起始日从 26 改成 1 后，顶部范围与合计按自然月重算
- 法定节假日（如 2026 年国庆）当天整段算加班；调休上班的周六按 19:00 后的规则算
- 关闭自动识别后，同一天回到按工作日设置判断
- 设置页“立即更新”能拉到新一年数据并显示新的覆盖范围；断网时提示失败且旧数据仍可用
- 所有数据在重启容器后仍存在
